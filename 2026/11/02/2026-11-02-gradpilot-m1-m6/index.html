一天六个里程碑

11 月 1 日，GradPilot 从一份设计文档开始。11:45 文档落盘，12:47 第一个提交，17:16 第六个提交。六个里程碑，六个 commit。这不是六天，是一天里的六次推进。

先画边界，再写代码

GradPilot 是一个毕业设计智能辅导平台，两个角色：

  • 教师端：对论文做初步审查——格式与结构用规则查，分章内容用 LLM 看，选题重复度跟历届库比。
  • 学生端：用自然语言查资料、找历年类似选题、让 Agent 基于自己的初稿做引导式提问；回答要带引用溯源卡片。

技术栈是单体内核：React 19 + Vite + TypeScript 的前端，FastAPI 的后端，SQLite 存业务数据，LanceDB 存向量，聊天走 SSE，认证走 JWT。设计文档里把八项 Agent 能力全部列成 first-party：个性化、记忆、子智能体、插件、MCP、技能、命令、钩子。graphs 只依赖 Kernel 接口，不直接碰具体实现——这是以后拆成独立 worker 或独立服务的前置条件。

先单体不是偷懒。一个人要在一天里做出能演示的东西，单条 uvicorn 命令启动、一个 SQLite 文件、一个前端 dev server，比微服务省掉大量“服务发现”和“端口对不上”的时间。边界留在代码里，不留在部署图上。

几个真正决定形状的实现

SSE 只做单向流。 聊天接口把 token、工具调用、来源、结束、错误拆成不同事件：

前端按事件名分支：token 逐字追加，tool_call 显示“正在检索 arXiv…”，sources 渲染来源卡片，done 解锁输入框，error 显示错误。工具执行进度和最终答案走同一条流，不用轮询。

Provider 抽象让测试不依赖 key。 智谱、DeepSeek、ollama、fake 四个实现共用一套接口。fake 返回固定回复，后端测试不需要网络、不需要 API key；演示时切到 ollama 的 qwen2.5:7b，embedding 用 bge-m3。

摄取是章节感知的。 docx 按 Heading 1/2 提章节树；pdf 用字号和加粗做启发式，失败标 parsed_partial，不静默丢内容。每个（章，节）成一个 chunk，超过 1000 字按段落续切，chunk 带 breadcrumb，比如 第3章 系统设计 > 3.2 模块A。学生初稿和历届库同表，检索时按 visibility 过滤：学生只能检到公开库和自己的稿子。

审查是三段拼起来的。 第一段是确定性规则：章节完整性、图表编号跳号/重复、GB/T 7714 著录正则、字数统计；第二段让 reviewer-agent 按章输出结构化 JSON（优点、带原文引用的问题、修改建议）；第三段把题目和摘要做 embedding，检索历年 top-k，让 LLM 归纳选题重复度和差异化建议。三段汇成一份 Markdown 报告，前端渲染，浏览器打印就是 PDF。

记忆分短期和长期。 短期是会话消息滑动窗口，默认近 20 条，超限用快模型摘要；长期是 memories 表加 LanceDB 向量表，每 8 轮触发一次反思，LLM 提炼候选，和既有记忆相似度超过 0.92 就跳过，每轮取 top-5 注入 system prompt。

MCP 工具是动态进来的。 管理页添加 server，支持 stdio 和 streamable-http；连接后 list_tools，工具名加前缀 mcp__<server>__，调用写 mcp_calls 审计表。演示用的计算器 server 提供 calc_add 和 now_time，学生说“请务必使用计算器工具算 123 加 456”，回答 579，审计记录约 8 ms。

打包、测试与没收拾完的尾巴

晚上把前端构建、后端打成 PyInstaller onedir 便携包：产物 571 MB，gradpilot.exe 约 30 MB，.env 和 data/ 放在 exe 同级，换机器不用装 Python/Node。目标机器仍然要装 ollama 并拉模型，或者改用云端 API key；杀软对 PyInstaller 产物可能误报，这是打包方式带来的，不是程序本身。

验证结果分两半：

  • 前端：11 条测试全过，vite build 154 ms，JS 258.47 kB（gzip 81.90 kB）。
  • 后端：81 条测试，77 过、4 挂。4 条失败全部在 test_student_graph.py；单独跑这个文件，4 条又全过。也就是说，功能单跑是通的，整套跑挂更像测试之间的共享状态/顺序问题，而不是业务逻辑坏了。下一步先查隔离和事件循环，不要先改业务。

还有 804 条 warning，能看到 datetime.utcnow() 的弃用提示；README 还停在“M1 骨架完成”，git log 已经到 M6。文档落后于代码，也是债。M7 的打磨还没开始。

能演示不等于能交付

一天六个里程碑，靠的不是打字快，是每个里程碑先有一句可验收的话：

  • M1：登录后能流式聊天。
  • M2：上传 docx 能解析、能检索到 chunk。
  • M3：学生问“历届有没有类似选题”，回答带来源卡片。
  • M4：教师发起审查，能拿到三段报告并打印。
  • M5：连续聊 8 轮后，新问题能体现之前的偏好。
  • M6：添加一个 MCP server，工具能进 Agent 并被审计。

每句话都能当场演示，里程碑才不会变成“代码写完了但不知道对不对”。

能演示也不等于能交付。4 条顺序相关的失败、M7 的打磨、README 的同步，都是下一步。先让演示稳定，再谈规模。
