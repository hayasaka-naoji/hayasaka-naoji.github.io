P14：函数把一坨 while 拆开

P14 的主线只有一句话：把 P13 那一坨 while 拆开，一个功能一个 def。函数的三个问题是：叫什么名字、要喂什么、吐不吐东西。

print 和 return 是两条出口。print 出去的东西人看得见，程序拿不到；return 出去的东西程序能接着算。P13 的通讯录只能打印、不能存档，根子就在这里。今天起立规矩：函数只负责算和返回，打印交给调用方。

没写 return 的函数，返回值是 None。print 自己也是这种人：z = print("hi")，先打 hi，z 是 None。更麻烦的是 None 会一路传下去：pass 的函数返回 None，total = add_contact(...) 拿到 None，最后打印出 共 None 人，没有 traceback，没有红字，程序“正常运行”，结果毫无意义。

return k, v 返回的是一个元组，不是两个值。可以整接、可以拆、可以下标：

局部变量是另起一间房。函数里的 pin = 99 改不到外面的 pin；但 list 传进去是本体，book.append(...) 外面看得见。两个现象相反，两个都对。第 7 周讲“引用 vs 拷贝”时再细拆。

今天踩的坑很集中：

  • import 会执行整个被导入文件。 PyCharm 自动塞了三个 import，一执行，day09_exercises.py 顶层那些 print 全跑了一遍，输出前面凭空多出 25 行旧内容。
  • clamp 条件顺序反了。 clamp(50, 0, 100) 返回 100；先判上界，再判下界，两头都没出界才原样。
  • parse_report 按 "\n" 切。 题面是按 ": " 切，三题全走“解析失败”。
  • int(k) 潜伏。 键是字符串，只有值是数字；修好第一个 bug，第二个才露头。
  • 自查表打勾走过场。 输出里“出现了”就当 ✅，实际 clamp 是 10/100/100、parse 三题全失败。“出现”不等于“对了”，每条要拿题面的期望值逐字比一遍。

结果：跟敲 6/6，门票 5/5（含一条自发更正），练习首轮 2/4、改后 4/4，收尾题七步通过。day13_contacts.py 的主循环只剩四步：问姓名、问电话、调用 add_contact、打印。

P15：课件先埋钉子

10 月 31 日写好了 P15《作用域与默认参数》的课件 day14_scope_defaults.py，函数体还留着 pass，这一课还没正式跑。课件里埋了三扇暗门：

  1. 函数里“读”外面的变量，直接读得到。
  2. 函数里一出现赋值，Python 就认定它是局部变量，从头到尾都是自己那间房；真要改外面的，得挂 global。
  3. 默认参数在 def 那一刻就算好、冻住，不是每次调用现算。

第三扇门后面是今天最该先记住的坑：

[] 是 def 时造出来的一个列表，两次调用共用同一个。add_cmd_bug("r") 得到 ['r']，再来一次 add_cmd_bug("s") 得到 ['r', 's']，第二次凭空多了一个 'r'。C 里对应的就是 static 局部变量：只初始化一次，之后一直活着。
