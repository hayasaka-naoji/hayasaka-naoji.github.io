缺一条算没交

三十号，考核②和 P14 挤在一天。

口试五题，第一次零补讲。list 与 tuple 只差可变性；ports["LED4"] = 4 与 ports["LED1"] = 9 都是插入/更新，炸的是读取缺失键；"confirmed: 42".split() 得到 ['confirmed:', '42']；raw.strip() 丢新串、原串不变；三种“没找到”分别是 KeyError、in 返回布尔、find 返回 -1。答完自己都觉得顺。

实操是 day11_exam.py，32 行，一个串口报文解析器。关键不是 if，是解包之前先数块数：parts = clean.split(": ")，len(parts) != 2 就报格式错误，块数对了才 dev, cmd = parts。后面两个 strip() 和 if not dev or not cmd 是额外防守，LED1 : on 也能吃，: on、LED1: 不会崩。

问题是验收单列了四个分支，实跑只交了三个，缺的是空回车。判卷时我独立补跑了缺的两例，程序没问题，但“证据”少一条。这已经是 P10 连着欠到 P13 的第四次同族问题。规矩今天定死：验收单上有几条，就跑几条，缺一条算没交。

下午 P14，函数。主线只有一句话：把 P13 那一坨 while 拆开，一个功能一个 def。函数的三个问题是：叫什么名字、要喂什么、吐不吐东西。print 和 return 是两条出口——print 出去的东西人看得见，程序拿不到；return 出去的东西程序能接着算。P13 的通讯录只能打印、不能存档，根子就在这里。

没写 return 的函数返回 None，print 自己也是。z = print("hi")，先打 hi，z 是 None。更麻烦的是 None 会一路传下去：total = add_contact(...) 拿到 None，最后打印“共 None 人”，没有 traceback，没有红字，程序“正常运行”，结果毫无意义。

今天踩的坑很集中。import 会执行整个被导入文件，PyCharm 自动塞的三个 import 一跑，day09_exercises.py 顶层那些 print 全出来，输出前面凭空多 25 行旧内容。clamp 条件顺序反了，clamp(50, 0, 100) 返回 100；parse_report 按 "\n" 切，题面要的是 ": "，三题全走“解析失败”；int(k) 潜伏在后面，修好第一个才露头。最要命的是自查表打勾走过场：输出里“出现了”就打勾，实际 clamp 是 10/100/100、parse 三题全失败。“出现”不等于“对了”，每条要拿题面的期望值逐字比一遍。

结果：跟敲 6/6，门票 5/5，练习首轮 2/4、改后 4/4，收尾题七步通过。晚上把 day13_contacts.py 的主循环压到四步：问姓名、问电话、调用 add_contact、打印。

今天两件事其实是一件事：口试答对，不等于验收单交齐；输出里出现过，不等于结果对了。

安！
